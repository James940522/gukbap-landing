# 커서 자산

사용자가 제공한 순서대로 `default`, `hover`, `click`, `text`입니다.
이 폴더의 PNG는 원본 해상도에서 투명 여백을 제거한 자산이며,
`public/asset/cursor`의 PNG는 실제 CSS 커서용 축소본입니다.

원본에 이미 알파 채널이 있어 그림을 다시 그리거나 배경을 생성하지 않았습니다.
화면 밖에 흩어진 거의 투명한 픽셀(알파 8/255 미만)을 제거한 뒤,
나머지 픽셀의 바운딩 박스까지 크롭했습니다. 흰 테두리와 호버의 빛 효과는 유지합니다.
원본 입력 파일은 수정하지 않았습니다.

| 상태 | 크롭된 자산 | 브라우저 PNG 크기 | 핫스팟 (x, y) |
| --- | --- | --- | --- |
| 기본 | default.png | 37 × 40 | 2, 1 |
| 호버 | hover.png | 40 × 46 | 5, 4 |
| 클릭 | click.png | 37 × 40 | 5, 1 |
| 텍스트 | text.png | 18 × 32 | 9, 16 |

숟가락 본체의 높이는 세 상태 모두 약 40px입니다. 호버는 빛 효과 때문에
전체 캔버스가 더 큽니다. 숟가락의 왼쪽 위 흰 테두리 끝을 기준으로 핫스팟을
각각 계산해, 효과의 가장자리나 투명한 캔버스 모서리가 클릭 지점이 되지 않게 했습니다.
텍스트 커서는 I자 중심을 사용합니다.

`manifest.json`에는 원본 파일명, 크롭 영역, 원본 좌표와 최종 핫스팟이 있습니다.
좌표 계산은 `round((원본 좌표 - 크롭 시작점) × 축소본 크기 / 크롭 크기)`입니다.
자산 크기를 바꾸면 `src/app/cursors.css`의 핫스팟도 함께 재계산해야 합니다.

CSS 네이티브 커서 방식을 사용한 `gopdoritang`, `omurice-landing`, `udon-landing`을
참고했고, 클릭 상태는 우동 프로젝트처럼 포인터 이벤트로 관리합니다.
마우스가 있는 환경에서만 적용하며, 터치 입력에는 적용하지 않습니다.
입력창은 드래그 중에도 텍스트 커서를 유지하고, 비활성 컨트롤은 `not-allowed`를 표시합니다.
이미지 로딩 실패 시 각 상태의 브라우저 기본 커서로 대체됩니다.
