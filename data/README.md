# 뚝손국밥 매장 데이터 관리

실제 매장 데이터는 `data/stores.csv` 한 파일에서 관리합니다. 초기 파일은 헤더만 있으며,
확인되지 않은 매장 정보를 넣지 않았습니다. 오므라이스의 매장 데이터나 키는 사용하지 않습니다.

## 등록 · 수정 · 폐점

CSV를 UTF-8로 저장하고 첫 행의 컬럼명을 유지하세요.

```csv
id,region,name,address,latitude,longitude,phone,status
```

| 컬럼 | 작성 방법 |
| --- | --- |
| `id` | 변경하지 않는 고유 매장 코드. 중복 불가. 앞의 0도 유지됩니다. |
| `region` | 검색에 사용할 지역명. 필수. |
| `name` | 실제 매장 표시명. 필수. |
| `address` | 실제 도로명 주소. 필수. 상세주소도 사용자에게 그대로 표시합니다. |
| `latitude` | 위도. `longitude`와 함께 입력하거나 둘 다 비웁니다. |
| `longitude` | 경도. `latitude`와 함께 입력하거나 둘 다 비웁니다. |
| `phone` | 실제 매장 연락처. 없으면 비웁니다. |
| `status` | `OPEN` 또는 `CLOSED`. `OPEN`만 목록과 지도에 표시됩니다. |

1. **신규 등록:** 확인된 매장 정보를 새 행에 추가하고 중복되지 않는 `id`를 지정합니다.
2. **정보 수정:** 해당 행의 지역, 매장명, 주소, 연락처를 수정합니다.
3. **주소 변경:** 기존 좌표가 있으면 새 좌표로 교체하거나 두 좌표를 모두 비웁니다.
   명시적으로 입력한 좌표는 우선 사용되므로 주소만 변경해도 자동 교체되지 않습니다.
4. **폐점:** `status`를 `CLOSED`로 변경합니다. 영구 삭제하려면 해당 행을 삭제합니다.

쉼표, 줄바꿈 또는 큰따옴표가 포함된 셀은 CSV 표준에 맞게 큰따옴표로 감쌉니다.
셀 안의 큰따옴표는 `""`로 작성합니다. Excel/스프레드시트에서 UTF-8 CSV로 내보내도 됩니다.
중복 ID나 잘못된 헤더/CSV 문법은 데이터 오류 응답으로 처리됩니다.
필수값 누락, 잘못된 좌표나 상태를 가진 행은 제외되고 경고가 반환됩니다.

## 반영 시점

- **개발:** 파일을 저장하고 새로고침합니다. `/api/stores`는 매번 CSV를 다시 읽습니다.
- **운영:** 변경된 CSV를 Git에 포함하고 재배포합니다. 실행 중인 서버에 파일을 동기화하는 기능은 없습니다.
- CSV는 공개 정적 디렉터리에 두지 않습니다. Next.js 파일 추적 설정으로 서버 배포에 포함합니다.

## 카카오 설정

`.env.example`의 기존 문의 설정을 유지하고, `.env.local`에 다음 두 값을 추가합니다.
반드시 **뚝손국밥 앱(ID `1607607`)**의 키를 사용하세요.

```dotenv
NEXT_PUBLIC_KAKAO_MAP_KEY=
KAKAO_REST_API_KEY=
```

- `NEXT_PUBLIC_KAKAO_MAP_KEY`: JavaScript 키. 브라우저 지도 SDK에서 사용되며 공개되는 값입니다.
- `KAKAO_REST_API_KEY`: REST API 키. 서버에서만 사용합니다. `NEXT_PUBLIC_` 접두어를 붙이지 않습니다.
- `.env.local`은 Git에 포함하지 않습니다. 배포 환경에도 같은 변수명을 등록합니다.
- JavaScript 키는 빌드 시 반영되므로 설정 변경 후 개발 서버를 재시작하거나 재빌드·재배포합니다.
- [카카오 지도 준비 가이드](https://apis.map.kakao.com/web/guide/)에 따라
  사용하는 로컬 주소와 운영 도메인을 해당 JavaScript 키의 SDK 도메인에 등록합니다.
  예: `http://localhost:3000`. `127.0.0.1`로 접속하면 그 주소도 등록합니다.
- 해당 앱의 지도 사용 활성화 및 Local API 사용 권한·쿼터를 확인합니다.
  키 미설정·SDK 실패 시에도 매장 목록은 이용할 수 있습니다.

## 좌표 변환과 캐시

입력된 위도·경도가 있으면 외부 API를 호출하지 않습니다. 둘 다 비어 있으면 서버가
원본 주소, 상세정보를 정제한 주소, 주소가 일치하는 키워드 결과 순서로 좌표를 찾습니다.
원본 주소는 변경하지 않습니다. 불확실한 키워드 결과는 사용하지 않습니다.

주소와 키 구분값을 기준으로 성공 좌표를 24시간 메모리 캐시하고, 동일 주소의 동시 호출을 합칩니다.
주소가 바뀌면 이전 주소 캐시를 사용하지 않습니다. 서버 재시작·서버리스 인스턴스 교체 시
캐시는 사라지며 여러 인스턴스 사이에 공유되지 않습니다. 반복 변환 비용을 줄이려면 검증한 좌표를
CSV에 직접 저장하세요. 별도의 DB나 캐시 파일은 만들지 않습니다.

좌표 변환에 실패해도 매장 행은 목록에 유지되며 핀은 표시하지 않습니다.
좌표가 없으면 길찾기 대신 카카오맵에서 주소를 검색할 수 있습니다.
API는 `{ stores, total, withCoordinates, warnings }` 형식으로 응답합니다.
진단에는 키와 카카오의 원문 에러를 포함하지 않습니다.

## 화면과 검증

메인페이지의 매장찾기 섹션과 헤더·모바일 메뉴·푸터의 매장찾기 링크는 임시 비노출 상태입니다.
공개 `/stores` 페이지와 공통 매장찾기 컴포넌트, API는 유지합니다. 별도 미리보기 페이지는 없습니다.
서버가 CSV의 OPEN 목록을 최초 HTML에 제공하며, 지도 좌표는 이후 API로 갱신합니다.
좌표 API 갱신이 실패해도 서버에서 읽은 주소·전화 목록은 유지됩니다.
매장 0건·CSV 오류일 때 `/stores`는 검색 제외 및 사이트맵 제외 상태를 유지합니다.

```bash
pnpm install
pnpm dev
node --test tests/stores.test.mjs tests/store-client.test.mjs
pnpm exec tsc --noEmit
pnpm lint
pnpm build
```

테스트용 매장·응답은 테스트 안에서만 사용합니다. 실제 CSV에는 넣지 않습니다.
자동 테스트는 CSV 검증·캐시·모의 카카오 응답과 SDK 동작을 확인합니다.
실제 지도 타일·핀·주소 변환·길찾기 도착지는 신규 앱의 키·권한 및 실제 매장 자료를 설정한 후
별도로 확인해야 합니다.

완료한 검사와 미검증 범위는 [구현·검증 기록](verification.md)을 참고하세요.
